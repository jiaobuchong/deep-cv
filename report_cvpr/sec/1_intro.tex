\section{Introduction}
\label{sec:intro}

Large pretrained Vision Transformers~\cite{dosovitskiy2021vit,steiner2022augreg} are usually not trained from scratch.
Instead, they are adapted to a new task, either by fine-tuning all weights or by training a small number of added parameters~\cite{houlsby2019adapter,hu2022lora,chen2022adaptformer}.
In this project we adapt ViT-B/16 to a fine-grained classification dataset with 10,000 classes whose names are hidden.
The training set has 450,000 images, exactly 45 per class.
The validation set (50,000 images, 5 per class) and the test set (100,000 images, 10 per class) have hidden labels and are scored on CodaBench.
Each training run may use at most 2 hours on 48\,GB of GPU memory (96\,GB$\cdot$h), and for every method we report four numbers: top-1 accuracy, trainable parameters, inference latency and training GPU-hours.

Two things make this task different from common transfer-learning benchmarks.
First, the new classifier head is large, but each class has few images.
A $10{,}000 \times 768$ linear head has 7.69M parameters: 9.0\% of the 85.8M-parameter backbone and 26$\times$ more than a rank-8 LoRA on the attention layers.
Yet each row of the head is trained on only 43--45 images.
Second, the budget is tight.
One epoch of full fine-tuning takes about 7 minutes on an A100, so only about eight epochs fit into one run.

This leads to three questions.
(1)~How should we start the new head?
(2)~Which adaptation method should we use, and where should its trainable parameters go?
(3)~How should we split the budget between epochs, data and test-time computation?
To answer them we ran 26 runs, changing one setting at a time.
We choose models on a local holdout split, whose accuracy is within 0.3 points of the CodaBench validation score.
Our contributions are:
\begin{itemize}[leftmargin=*,itemsep=1pt,topsep=2pt]
    \item \textbf{A better start for the head.} The common linear-probe (LP) head, which LP-FT~\cite{kumar2022lpft} trains on frozen features before fine-tuning, hurts in our task. Starting from class-mean prototypes~\cite{qi2018imprinted} instead adds 2.1--3.1 points for full fine-tuning, LoRA and AdaptFormer. A random head does as well as the prototype head, so the harm comes from fitting the head on the training images (\cref{sec:ablation-head}).
    \item \textbf{Seven adaptation methods under one protocol.} Small changes in every block give much more accuracy per parameter than fine-tuning the top blocks: LoRA on all linear layers (1.375\% of the backbone) matches the last four blocks (33\%), and BitFit (0.12\%) beats the last block (8.3\%). LoRA is the most accurate of the efficient methods (98\% of full fine-tuning), but only 0.44 points ahead of the Adapter; its real advantage is that it can be merged into the weights, so it adds no latency, while the two adapters add 33--40\%. Training memory depends on how far back the gradients go, not on how many parameters are trained, so an efficient method can still need a lot of memory (\cref{sec:compare}).
    \item \textbf{Full cost reporting.} For every run we report accuracy, trainable parameters, latency, GPU-hours and peak memory. Our final models reach 76.22\% (full fine-tuning, $+$5.4 over the reference) and 71.90\% (LoRA, $+$3.6 over the reference LoRA) on the CodaBench validation set, and 76.09\% and 71.67\% on the test set.
    \item \textbf{The whole process.} We describe the study round by round, including the ideas that failed (\cref{sec:process}). After the deadline we found that larger input images add another 4.4 points (\cref{sec:post}).
\end{itemize}
